# Schema boundary

`CompileREST` and `CompileGraphQL` return immutable compiled schemas. `NormalizeREST(spec, request)` is the one-shot REST entry point. Compiled schemas provide `Normalize`, `Catalog` and `Digest`. GraphQL additionally provides `NormalizeHTTP` for its strict POST JSON envelope. HTTP normalization restores the bounded request body for forwarding. Neither package API authenticates callers, selects an upstream, classifies risk, grants permissions, or sends network requests.

`Request.Fields` is an ordered **occurrence list**. Coordinates use actual schema names, such as `Mutation.commentCreate`. Paths use response aliases and preserve nesting. Repeated fields and repeated fragment spreads remain separate occurrences with separately resolved arguments. Both true and false `@include`/`@skip` branches are retained for conservative authorization. Runtime abstract-type conditions are likewise not used to remove authorization requirements.

## Supported subset and limits

- OpenAPI input is JSON with version 3.0.x or 3.1.x. This is a narrow request importer, not a complete OpenAPI validator. Descriptions/examples do not confer permissions. Response bodies are not validated, although reference targets anywhere in the document must resolve.
- Operations use explicit unique `operationId`, or the fallback `METHOD /template`. Paths contain complete-segment variables with declared required scalar path parameters. Equivalent or overlapping templated routes for a method are rejected rather than guessing how a provider router orders them. Fully concrete literal paths outrank variable templates, independent of map iteration order.
- Query/path parameters support string, boolean, integer and number. Query uses scalar `form`, path uses scalar `simple`. Duplicate declarations, header/cookie parameters, parameter arrays/objects, nullable parameters, alternative serialization, and `allowReserved` are rejected.
- Body media type is `application/json`, optionally `charset=utf-8`. Objects are closed even when `additionalProperties` is omitted. Explicit `additionalProperties: true` or schema-valued additional properties are rejected. Arrays, required fields, enum, nullable, numeric minimum/maximum, string length/pattern, and array item counts are supported. Integer values must be mathematically integral and fit signed int64. Path/query integer spelling is canonical decimal. Numbers use exact rational bound comparisons, with at most 256 characters and decimal exponent magnitude 308.
- Only local `#/components/schemas/Name` references without siblings or escaped names are supported. Unknown references and recursive component schemas fail import, including unused components. Polymorphism, discriminator, defaults, format annotations, callbacks, extensions, security schemes, nonempty security requirements, server variables/base paths, and unrecognized request-schema keywords fail import. Configure authentication and upstream origins separately in the gateway.
- REST rejects percent-encoded paths, invalid UTF-8, backslashes, dot segments, empty path segments, unknown parameters, duplicate decoded query names, duplicate JSON members, invalid Unicode surrogates, trailing JSON data, unknown body fields, and undeclared bodies.
- GraphQL SDL and request syntax use `github.com/vektah/gqlparser/v2 v2.5.64`. The upstream default validation rules are applied. The package has its own strict coercer because the upstream variable coercer accepts cases outside this boundary, including numeric strings and case-insensitive enums.
- GraphQL supports named operation selection, fragments, aliases, nested fields, input objects, exact-case enums, builtin scalar inputs, singleton-to-list coercion and operation/argument/input-field defaults. Inputs are copied rather than mutating caller maps. `Int` is signed 32-bit. Numeric `ID` inputs are restricted to the exact IEEE-754 integer range, with larger IDs supplied as strings.
- GraphQL rejects subscriptions, JSON batching, introspection fields, persisted-query extensions, undeclared variables, unresolved fields/types/fragments, fragment cycles, fragment-local variables, operation/variable/fragment-definition directives, executable directives other than `include`/`skip`, and custom input scalar values. Applied schema directives other than `deprecated` and `specifiedBy` are rejected, including `oneOf` rather than silently ignoring its constraints. Builtin directive redefinitions and schema-root directives are rejected. Custom output scalar declarations are allowed.
- Documents are bounded to 4 MiB. HTTP bodies and query text are bounded to 1 MiB. JSON/value/selection nesting is bounded to 64. GraphQL request parsing is bounded to 32,768 tokens, SDL parsing to 200,000 tokens, and expanded selection traversal to 4,096 nodes per operation before invoking the query validator. Expansion counts fragment nodes as well as fields, including unselected operations and unused fragments. Expanded REST schema compilation is capped at 65,536 nodes. GraphQL normalization has an aggregate 65,536-node and 4 MiB string budget across variables, argument copies and response paths, preventing repeated selections or nested defaults from amplifying bounded inputs without limit.

The gateway must additionally enforce transport/header limits and refuse unsupported encodings, routing ambiguity, redirects and unexpected destinations. Full-access profiles can bypass schema requirements in the gateway without changing this package's restricted normalization rules.

## Catalogs

`Catalog` operations are sorted by ID. `Digest` uses SHA-256 over deterministic JSON structures. REST digests canonicalize JSON key ordering/whitespace and include the input document, including documentation. GraphQL digests canonicalize type/field/argument maps, union/interface/enum ordering, roots and directives, excluding descriptions and source positions. GraphQL operation signatures include transitively referenced input definitions and defaults. REST operation signatures contain resolved parameter/body schemas and all supported bounds. `Diff` reports sorted added, removed and changed IDs. `ValidateReferences` rejects unknown policy operation references. Catalog changes never grant access automatically.

## Dependency evaluation

Primary sources checked on November 9, 2026:

- OpenAPI 3.0.4: <https://spec.openapis.org/oas/v3.0.4.html>. Its parameter styles, reference rules, required-path rules and schema keywords define the subset above. Newer OpenAPI releases exist, but are not silently accepted as equivalent.
- GraphQL September 2025 specification: <https://spec.graphql.org/September2025/>. Named operation selection, builtin coercion, defaults and directive semantics inform the boundary.
- Pinned parser/validator source: <https://github.com/vektah/gqlparser/tree/v2.5.64>. The Go proxy reports v2.5.64 released October 22, 2026, requiring Go 1.25. The repository's Go toolchain satisfies that requirement. This dependency provides the dedicated grammar/SDL/query validator. A general-purpose OpenAPI dependency was not added because the accepted subset is intentionally smaller and unsupported security constructs must fail closed.

Fixture origins, source digests and reproduction commands are in `testdata/README.md`. Package tests perform no provider writes or network requests.
